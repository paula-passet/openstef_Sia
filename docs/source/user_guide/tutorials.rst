Tutorials
=========

This comprehensive tutorial covers everything you need to know to start using OpenSTEF effectively, from your first forecast to advanced backtesting and custom implementations.

.. note::
   OpenSTEF is a Python library, not a deployable application. You'll be writing Python code to create forecasting workflows using OpenSTEF's components.

Prerequisites
-------------

Before starting these tutorials, ensure you have:

- Python 3.8 or higher installed
- Basic familiarity with pandas and time series data
- Understanding of machine learning concepts (helpful but not required)
- OpenSTEF installed: ``pip install openstef``

First Use Tutorial
==================

This section walks you through creating your first forecast with OpenSTEF, covering data preparation, model training, forecasting, and evaluation.

Loading and Preparing Data
--------------------------

OpenSTEF expects time series data with specific columns and structure. The library includes data validation to ensure your data meets requirements.

**Required Data Schema**

Your input data should include:

- Timestamp column (datetime index)
- Load/demand values (target variable)
- Weather predictors (temperature, radiation, wind speed, etc.)
- Calendar features (automatically generated by OpenSTEF)

.. code-block:: python

   import pandas as pd
   from openstef.data_classes.prediction_job import PredictionJobDataClass
   from openstef.pipeline.train_model import train_model_pipeline
   
   # Load your time series data
   # Data should have datetime index and required columns
   data = pd.read_csv('your_energy_data.csv', index_col='datetime', parse_dates=True)
   
   # Validate data structure
   print(f"Data shape: {data.shape}")
   print(f"Date range: {data.index.min()} to {data.index.max()}")
   print(f"Columns: {list(data.columns)}")

**Data Validation**

OpenSTEF includes built-in data validation to check for common issues:

.. code-block:: python

   from openstef.validation import validate_data
   
   # Validate your data (checks for flatliners, missing values, etc.)
   validation_results = validate_data(data)
   if validation_results.has_errors:
       print("Data validation issues found:")
       for error in validation_results.errors:
           print(f"- {error}")

**Common Data Sources and Formats**

OpenSTEF can work with data from various sources:

- CSV files with datetime index
- Database connections (SQL, InfluxDB)
- Cloud storage (S3, Azure Blob)
- Real-time APIs

.. note::
   For production deployments, you'll typically integrate OpenSTEF with your existing data infrastructure using custom data fetchers.

Training a Model
----------------

OpenSTEF uses PredictionJob configurations to define forecasting tasks. Each job specifies the model type, features, and training parameters.

**Basic Model Training**

.. code-block:: python

   from openstef.data_classes.prediction_job import PredictionJobDataClass
   from openstef.pipeline.train_model import train_model_pipeline
   
   # Create a prediction job configuration
   prediction_job = PredictionJobDataClass(
       id=1,
       name="my_first_forecast",
       model="xgb",  # XGBoost model
       horizon_minutes=1440,  # 24-hour forecast horizon
       resolution_minutes=15,  # 15-minute resolution
       train_components=False,  # Single model (not split forecast)
   )
   
   # Train the model
   model_specs = train_model_pipeline(
       prediction_job=prediction_job,
       input_data=data,
       check_hyper_params=True
   )
   
   print(f"Model trained successfully: {model_specs.id}")

**Model Types Available**

OpenSTEF supports several model types:

- **XGBoost** (``xgb``): Default choice, good for most use cases
- **LightGBM** (``lgb``): Fast training, similar performance to XGBoost  
- **Linear models** (``linear``): Simple, interpretable, good for highly aggregated data
- **Ensemble models**: Available in openstef-meta module

**Training Options and Parameters**

.. code-block:: python

   # Advanced prediction job configuration
   prediction_job = PredictionJobDataClass(
       id=1,
       name="advanced_forecast",
       model="xgb",
       horizon_minutes=2880,  # 48-hour horizon
       resolution_minutes=15,
       train_components=True,  # Enable split forecasting
       quantiles=[0.1, 0.5, 0.9],  # Probabilistic forecasts
       feature_names=["load", "temp", "radiation", "windspeed"],
       hyper_params={
           "n_estimators": 100,
           "max_depth": 6,
           "learning_rate": 0.1
       }
   )

Creating a Forecast
-------------------

Once your model is trained, you can generate forecasts for future time periods.

**Running Inference**

.. code-block:: python

   from openstef.pipeline.create_forecast import create_forecast_pipeline
   
   # Create forecast using trained model
   forecast = create_forecast_pipeline(
       prediction_job=prediction_job,
       model_specs=model_specs,
       input_data=recent_data  # Recent data for context
   )
   
   print(f"Forecast shape: {forecast.shape}")
   print(f"Forecast period: {forecast.index.min()} to {forecast.index.max()}")

**Output Format and Probabilistic Forecasts**

OpenSTEF generates probabilistic forecasts with multiple quantiles:

.. code-block:: python

   # Forecast contains multiple quantiles
   print("Available columns:", list(forecast.columns))
   # Output: ['forecast', 'quantile_P10', 'quantile_P50', 'quantile_P90']
   
   # P50 is the median forecast (most likely outcome)
   # P10/P90 provide confidence intervals
   
   # Plot the forecast
   import matplotlib.pyplot as plt
   
   plt.figure(figsize=(12, 6))
   plt.plot(forecast.index, forecast['quantile_P50'], label='P50 (median)')
   plt.fill_between(forecast.index, 
                    forecast['quantile_P10'], 
                    forecast['quantile_P90'], 
                    alpha=0.3, label='P10-P90 confidence interval')
   plt.legend()
   plt.title('Energy Forecast with Confidence Intervals')
   plt.show()

Evaluating Performance
----------------------

OpenSTEF provides built-in metrics and evaluation tools to assess forecast quality.

**Built-in Metrics**

.. code-block:: python

   from openstef.metrics import calculate_metrics
   
   # Compare forecast with actual values
   metrics = calculate_metrics(
       y_true=actual_values,
       y_pred=forecast['quantile_P50'],
       quantiles=forecast[['quantile_P10', 'quantile_P90']]
   )
   
   print("Forecast Metrics:")
   print(f"MAE: {metrics['mae']:.2f}")
   print(f"RMSE: {metrics['rmse']:.2f}")
   print(f"MAPE: {metrics['mape']:.2f}%")

**Interpreting Reports**

Key metrics to understand:

- **MAE (Mean Absolute Error)**: Average prediction error in original units
- **RMSE (Root Mean Square Error)**: Penalizes larger errors more heavily
- **MAPE (Mean Absolute Percentage Error)**: Error as percentage of actual values
- **rMAE**: Relative MAE compared to naive baseline

**Visualization**

.. code-block:: python

   from openstef.plotting import plot_forecast_evaluation
   
   # Create evaluation plots
   plot_forecast_evaluation(
       actual=actual_values,
       forecast=forecast,
       title="Forecast vs Actual"
   )

Energy Split (Optional)
-----------------------

Energy split forecasting separates total load into components (e.g., solar, wind, base load).

**When to Use Energy Split**

- When you need component-level forecasts
- For better interpretability of forecast drivers
- When different components have different patterns

**How to Configure**

.. code-block:: python

   # Enable split forecasting
   prediction_job = PredictionJobDataClass(
       id=1,
       name="split_forecast",
       model="xgb",
       train_components=True,  # Enable split forecasting
       split_components=["solar", "wind", "other"]
   )
   
   # Training automatically handles component separation
   model_specs = train_model_pipeline(
       prediction_job=prediction_job,
       input_data=data
   )

Backtesting
===========

Backtesting evaluates how well your model would have performed on historical data, providing crucial insights into model reliability and performance over time.

What Backtesting Tests
----------------------

Backtesting simulates real-world forecasting by:

- Training models on historical data
- Making forecasts for subsequent periods
- Comparing forecasts with actual outcomes
- Repeating this process across multiple time periods

This reveals how model performance varies over time and under different conditions.

How to Run a Backtest
---------------------

.. code-block:: python

   from openstef.pipeline.create_backtest import create_backtest_pipeline
   
   # Configure backtest parameters
   backtest_config = {
       'start_date': '2023-01-01',
       'end_date': '2023-12-31',
       'train_window_days': 365,  # Use 1 year of data for training
       'forecast_horizon_hours': 24,
       'step_size_days': 7  # Move forward 1 week at a time
   }
   
   # Run backtest
   backtest_results = create_backtest_pipeline(
       prediction_job=prediction_job,
       input_data=historical_data,
       **backtest_config
   )

**Interpreting Backtest Results**

.. code-block:: python

   # Analyze backtest performance
   print("Backtest Summary:")
   print(f"Number of forecast periods: {len(backtest_results)}")
   print(f"Average MAE: {backtest_results['mae'].mean():.2f}")
   print(f"MAE standard deviation: {backtest_results['mae'].std():.2f}")
   
   # Plot performance over time
   import matplotlib.pyplot as plt
   
   plt.figure(figsize=(12, 6))
   plt.plot(backtest_results.index, backtest_results['mae'])
   plt.title('Model Performance Over Time (Backtest)')
   plt.ylabel('Mean Absolute Error')
   plt.xlabel('Date')
   plt.show()

Custom TargetProvider
---------------------

TargetProviders define how OpenSTEF accesses your target data (the values you want to forecast).

**When to Implement Custom TargetProvider**

- Your data source isn't supported by default providers
- You need custom data preprocessing or aggregation
- You're integrating with proprietary data systems

       def validate_data(self, data):

           # Implement validation specific to your data

Custom Workflows
----------------

OpenSTEF's modular design allows you to customize training and inference workflows.

**Extending Default Workflows**

.. code-block:: python

   from openstef.pipeline.train_model import train_model_pipeline
   from openstef.feature_engineering import apply_feature_engineering
   
   def custom_training_workflow(prediction_job, input_data):
       """Custom training workflow with additional preprocessing."""
       
       # Custom preprocessing step
       processed_data = custom_preprocessing(input_data)
       
       # Apply OpenSTEF feature engineering
       features = apply_feature_engineering(processed_data, prediction_job)
       
       # Custom feature selection
       selected_features = custom_feature_selection(features)
       
       # Use standard OpenSTEF training
       model_specs = train_model_pipeline(
           prediction_job=prediction_job,
           input_data=selected_features
       )
       
       return model_specs

**Custom Inference Pipeline**

.. code-block:: python

   def custom_forecast_workflow(prediction_job, model_specs, input_data):
       """Custom forecasting with post-processing."""
       
       # Standard OpenSTEF forecast
       raw_forecast = create_forecast_pipeline(
           prediction_job=prediction_job,
           model_specs=model_specs,
           input_data=input_data
       )
       
       # Custom post-processing
       processed_forecast = custom_postprocessing(raw_forecast)
       
       return processed_forecast
