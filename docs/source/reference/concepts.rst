Forecasting Concepts
====================


Understanding Forecast Results
------------------------------


Understanding the outputs generated by OpenSTEF forecasting models is crucial for effectively utilizing this library in your energy forecasting applications. OpenSTEF produces structured forecast datasets that contain not only the predicted values but also associated metadata, confidence intervals through quantiles, and feature contribution information that helps explain model decisions. These outputs follow a standardized format that includes temporal information, prediction job identifiers, and location-specific details, making it essential to understand how to interpret each component correctly. Whether you're integrating forecasts into operational systems, validating model performance, or explaining predictions to stakeholders, a solid grasp of the forecast output structure will enable you to extract maximum value from OpenSTEF's forecasting capabilities and make informed decisions based on the model's predictions.


.. code-block:: python

   import pandas as pd
   import numpy as np
   from datetime import datetime, timedelta

   # Example forecast result dataframe structure
   forecast_start = datetime(2023, 10, 15, 9, 0)
   forecast_periods = 96  # 24 hours at 15-minute intervals

   # Create datetime index for forecast horizon
   forecast_index = pd.date_range(
       start=forecast_start,
       freq='15T',
       periods=forecast_periods
   )

   # Typical forecast result dataframe
   forecast_result = pd.DataFrame({
       'forecast': np.random.uniform(50, 150, forecast_periods),  # MW
       'forecast_quantile_P10': np.random.uniform(30, 120, forecast_periods),
       'forecast_quantile_P90': np.random.uniform(70, 180, forecast_periods),
       'horizon': np.arange(0.25, 24.25, 0.25),  # hours ahead
       'pid': [123] * forecast_periods,  # prediction job id
   }, index=forecast_index)

   # Add metadata columns for wind power forecasts
   forecast_result['lat'] = 52.1326
   forecast_result['lon'] = 5.2913
   forecast_result['turbine_type'] = 'Vestas_V90_2000'
   forecast_result['n_turbines'] = 25
   forecast_result['hub_height'] = 105  # meters

   print(forecast_result.head(10))
   print(f"\nForecast shape: {forecast_result.shape}")
   print(f"Forecast period: {forecast_result.index[0]} to {forecast_result.index[-1]}")


OpenSTEF forecast outputs are structured as pandas DataFrames containing multiple columns that provide comprehensive information about each prediction. The primary forecast column contains the predicted values (e.g., energy demand or production) for each timestamp in the forecast horizon. Quantile columns (such as q10, q25, q75, q90) provide uncertainty estimates by showing different probability levels of the forecast, enabling users to assess prediction confidence and risk. The datetime index represents the forecast timestamps, typically at 15-minute intervals. Additional metadata columns may include prediction job identifiers (pid), geographical coordinates (lat, lon), and technical specifications like turbine_type, n_turbines, and hub_height for wind power forecasts. Feature contribution columns, when available through explainable forecasting models, show how individual input features influenced each prediction, providing valuable insights into model behavior and forecast drivers.

When interpreting OpenSTEF forecast results, understanding accuracy and reliability requires examining multiple dimensions of model performance. The library provides quantile forecasts that express uncertainty ranges around point predictions, allowing you to assess not just the expected value but also the confidence intervals. The `score` method returns `SubsetMetric` objects that evaluate model performance across different forecast horizons, helping you understand how accuracy degrades with longer lead times. For deeper insights, the `predict_contributions` method reveals which features most strongly influence specific predictions, enabling you to identify when forecasts might be less reliable due to unusual input conditions. The `max_horizon` property indicates the furthest reliable forecast distance, beyond which accuracy typically decreases significantly. When evaluating forecast reliability, consider both the statistical metrics from the scoring functions and the feature importance patterns - forecasts based on stable, well-understood input patterns are generally more reliable than those driven by volatile or sparse features.


Quantiles and Confidence Intervals
----------------------------------


Traditional forecasting methods produce point forecasts - single predicted values for future time periods. However, real-world energy systems require understanding of forecast uncertainty to make informed decisions about grid operations, trading, and resource allocation. OpenSTEF addresses this need through probabilistic forecasting, which provides not just a single prediction but a full probability distribution of possible outcomes. This approach enables quantile predictions at different confidence levels, allowing users to assess both the most likely scenario and the range of potential outcomes. By generating confidence intervals and quantile forecasts, OpenSTEF helps energy professionals quantify uncertainty and make risk-informed decisions based on the full spectrum of possible future conditions.


.. code-block:: python

   # Generate quantile predictions using XGBQuantileOpenstfRegressor
   from openstef.model.regressors import XGBQuantileOpenstfRegressor
   import pandas as pd
   import numpy as np

   # Create sample training data
   X_train = pd.DataFrame({
       'load_lag_24': np.random.randn(1000),
       'temp': np.random.randn(1000) * 10 + 15,
       'hour': np.tile(range(24), 42)[:1000]
   })
   y_train = np.random.randn(1000) * 100 + 500

   # Initialize quantile regressor with multiple quantiles
   quantiles = [0.1, 0.25, 0.5, 0.75, 0.9]
   model = XGBQuantileOpenstfRegressor(quantiles=quantiles)

   # Fit the model
   model.fit(X_train, y_train)

   # Create sample prediction data
   X_pred = pd.DataFrame({
       'load_lag_24': np.random.randn(48),
       'temp': np.random.randn(48) * 8 + 12,
       'hour': list(range(24)) * 2
   })

   # Generate predictions for different quantiles
   median_pred = model.predict(X_pred, quantile=0.5)  # Median forecast
   lower_bound = model.predict(X_pred, quantile=0.1)  # Lower confidence bound
   upper_bound = model.predict(X_pred, quantile=0.9)  # Upper confidence bound

   # Create forecast DataFrame with quantile predictions
   forecast_df = pd.DataFrame({
       'forecast': median_pred,
       'quantile_0.1': lower_bound,
       'quantile_0.25': model.predict(X_pred, quantile=0.25),
       'quantile_0.5': median_pred,
       'quantile_0.75': model.predict(X_pred, quantile=0.75),
       'quantile_0.9': upper_bound
   })

   print("Forecast with quantile predictions:")
   print(forecast_df.head())

   # Calculate confidence intervals from quantiles
   forecast_df['ci_80_lower'] = forecast_df['quantile_0.1']
   forecast_df['ci_80_upper'] = forecast_df['quantile_0.9']
   forecast_df['ci_width'] = forecast_df['ci_80_upper'] - forecast_df['ci_80_lower']

Different quantile levels serve specific purposes in energy forecasting applications. The median quantile (0.5) provides the most likely forecast value and is commonly used for general planning purposes. Lower quantiles like 0.1 or 0.25 help identify conservative scenarios for risk management, ensuring sufficient energy reserves during periods of high uncertainty. Higher quantiles such as 0.75 or 0.9 are valuable for capacity planning and identifying potential peak demand scenarios. In grid operations, multiple quantile levels enable operators to assess the full range of possible outcomes, with extreme quantiles (0.05, 0.95) particularly useful for stress testing and contingency planning. The choice of quantile level depends on the specific use case - trading applications might focus on median predictions, while system reliability assessments require broader quantile ranges to capture uncertainty bounds.


- 10th percentile (P10): Used for conservative planning and risk management, representing scenarios where demand is lower than expected 90% of the time

- 25th percentile (P25): Lower quartile boundary, useful for identifying below-average demand scenarios and capacity planning buffers

- 50th percentile (P50): Median forecast representing the most likely outcome, equivalent to the point forecast in many applications

- 75th percentile (P75): Upper quartile boundary, helpful for identifying above-average demand scenarios and ensuring adequate supply

- 90th percentile (P90): Used for high-confidence planning where you need to cover demand in 90% of scenarios, critical for peak load preparation

- 95th percentile (P95): Near-maximum scenarios for extreme event planning and infrastructure sizing

- 5th and 95th percentiles: Common pairing for 90% confidence intervals in uncertainty quantification


.. note::

   Quantile predictions are essential for effective risk management in electrical grid operations. Unlike point forecasts that provide only a single expected value, quantile forecasts enable grid operators to understand the full range of possible outcomes and their associated probabilities. This probabilistic information is crucial for making informed decisions about grid balancing, reserve capacity planning, and contingency management. For example, the 10th percentile forecast helps operators prepare for low generation scenarios, while the 90th percentile indicates potential oversupply situations that may require curtailment actions.


Model Selection for Different Use Cases
---------------------------------------


OpenSTEF provides a comprehensive suite of machine learning models designed to handle diverse energy forecasting scenarios. The library includes traditional statistical models like ARIMA for time series analysis, gradient boosting models such as LightGBM and XGBoost for robust performance, linear regression variants including quantile regression for uncertainty estimation, and specialized models like DAZLS (Day-Ahead Zero Load Shedding) for specific energy market applications. Additionally, OpenSTEF offers fallback models for handling edge cases, ensemble methods through metamodels, and baseline models like Flatliner and Median for benchmarking purposes. This variety ensures that users can select the most appropriate forecasting approach based on their data characteristics, accuracy requirements, and computational constraints.


- XGBoost (XGB) - Gradient boosting models offering high accuracy for complex patterns, with support for quantile regression and multi-output forecasting

- Linear Regression - Fast, interpretable models ideal for simple relationships and baseline comparisons, including quantile variants for uncertainty estimation

- LightGBM (LGBM) - Memory-efficient gradient boosting alternative to XGBoost, suitable for large datasets with faster training times

- ARIMA - Traditional time series models for capturing seasonal patterns and trends in univariate forecasting scenarios

- Flatliner - Simple persistence model that uses the most recent value as the forecast, useful as a baseline reference

- Median - Robust baseline model that predicts the historical median value, resistant to outliers in training data

- DAZLS (Damped Additive Zero-Lag Smoothing) - Specialized smoothing model for handling irregular patterns in energy forecasting

- Custom Regressor - Flexible wrapper allowing integration of any scikit-learn compatible model into the OpenSTEF pipeline


Selecting the appropriate forecasting model in OpenSTEF depends on several key factors that should be carefully evaluated based on your specific use case. The primary considerations include the nature of your time series data, such as seasonality patterns, trend characteristics, and the presence of external influencing factors like weather conditions. Data availability constraints play a crucial role, particularly when dealing with delayed measurements or delayed weather forecasts, which may require models that can handle missing or incomplete information. The forecast horizon is another critical factor - short-term predictions may benefit from simpler models like linear regression or median-based approaches, while longer-term forecasts often require more sophisticated ensemble methods or gradient boosting models like LightGBM or XGBoost. Performance requirements must also be balanced against model complexity, as some applications demand real-time predictions with minimal computational overhead, favoring faster models like the flatliner or linear regressors, while others can accommodate more complex models that provide higher accuracy. Additionally, the need for uncertainty quantification should influence your choice, with quantile regression models being preferred when prediction intervals are essential for decision-making processes.


.. code-block:: python

When selecting models in OpenSTEF, you'll encounter fundamental trade-offs between accuracy, interpretability, and computational speed. Linear models like Linear and Linear Quantile regressors offer high interpretability and fast training/prediction times, making them ideal for scenarios where understanding feature relationships is crucial or when computational resources are limited. However, they may sacrifice accuracy for complex non-linear patterns. At the other end of the spectrum, ensemble methods like XGBoost (XGB) and LightGBM (LGBM) typically deliver superior accuracy by capturing intricate relationships in energy data, but come with reduced interpretability and higher computational costs. For middle-ground solutions, ARIMA models provide good interpretability for time series patterns while maintaining reasonable performance, though they may struggle with external features like weather data. The library also includes specialized models like DAZLS for specific use cases and fallback mechanisms like Flatliner and Median regressors that prioritize reliability and speed over accuracy when primary models fail. Consider your deployment constraints, stakeholder requirements for model explainability, and the criticality of forecast accuracy when making your selection, as OpenSTEF's modular architecture allows you to experiment with different models and evaluate these trade-offs systematically.


- XGBoost (xgb) - Best for complex non-linear patterns and high accuracy requirements, handles feature interactions well but requires more computational resources

- Linear Regression (linear) - Ideal when interpretability is crucial, provides clear coefficient-based explanations and fast training, suitable for simple relationships

- LightGBM (lgbm) - Excellent balance of speed and accuracy for large datasets, memory efficient with good performance on structured data

- Linear Quantile (linear_quantile) - Use when you need uncertainty quantification with interpretable linear relationships, provides prediction intervals

- XGBoost Quantile (xgb_quantile) - Combines XGBoost's pattern recognition with uncertainty estimation, ideal for risk-aware forecasting

- ARIMA (arima) - Traditional time series approach for data with clear seasonal patterns and when statistical modeling is preferred over machine learning

- Flatliner (flatliner) - Simple baseline model that predicts the most recent value, useful for benchmarking and very stable time series

- DAZLS (dazls) - Specialized for zero-inflated data where many observations are zero, common in renewable energy scenarios

- Median (median) - Robust baseline that predicts historical median values, good starting point and outlier-resistant benchmark


Important Predictors and Weather Dependency
-------------------------------------------


Understanding which features drive your forecasts is crucial for building reliable energy load predictions. OpenSTEF's machine learning framework automatically evaluates feature importance during model training, helping you identify the most influential variables in your forecasting models. Feature importance analysis reveals how much each input variable - whether it's historical load data, weather conditions, calendar information, or engineered features - contributes to the model's predictions. This insight is particularly valuable in energy forecasting where domain knowledge about factors like temperature sensitivity, seasonal patterns, and load dependencies can be validated and quantified through the model's feature importance scores.


.. code-block:: python

   # Train a model and extract feature importance
   from openstef.model.model_creator import ModelCreator
   from openstef.data_classes.model_specifications import ModelSpecificationDataClass
   import pandas as pd

   # Assume we have training data with features and target
   # training_data = pd.DataFrame with features like 'load_lag_24h', 'temperature', 'solar_radiation', etc.

   # Create model specification for XGBoost (supports feature importance)
   model_specs = ModelSpecificationDataClass(
       model_type="xgb",
       hyper_params={
           "n_estimators": 100,
           "max_depth": 6,
           "learning_rate": 0.1
       }
   )

   # Train the model
   model_creator = ModelCreator()
   trained_model = model_creator.create_model(
       model_specs=model_specs,
       input_data=training_data,

   )

   # Extract feature importance
   if hasattr(trained_model.model, 'feature_importances_'):
       # Get feature names and importance scores

       print("Top 10 Most Important Features:")

       # Examine weather-related features specifically

           importance_df['feature'].str.contains('temp|wind|solar|radiation|cloud')

       print("\nWeather-related feature importance:")

OpenSTEF models rely on several key categories of features to generate accurate energy load forecasts. Historical load patterns form the foundation, capturing both recent consumption trends and seasonal behaviors that repeat over time. Weather variables play a crucial role, particularly temperature, solar radiation, and wind speed, as these directly influence heating, cooling, and renewable energy generation. Time-based features encode cyclical patterns such as hour-of-day, day-of-week, and seasonal effects that reflect human activity patterns and energy usage habits. The library's feature engineering modules automatically create lag features from historical data, rolling statistics to capture trends, and weather-derived features that translate meteorological conditions into energy-relevant predictors. Holiday features account for atypical consumption during special days, while cyclic encoding ensures the model understands temporal relationships like the connection between 23:00 and 01:00 hours.


- Temperature: Primary driver for heating and cooling demand, with strong correlation to residential and commercial load patterns, particularly important for HVAC forecasting

- Solar irradiance: Critical for photovoltaic generation forecasting and affects net load predictions, with OpenSTEF's built-in feature engineering converting radiation data to PV generation estimates

- Wind speed and direction: Essential for wind power generation forecasts and influences cooling loads in industrial applications

- Humidity: Affects air conditioning demand and can impact industrial processes requiring climate control

- Cloud cover: Influences both solar generation potential and cooling/heating loads by affecting ambient temperature

- Precipitation: Impacts outdoor activities and can affect industrial operations, with indirect effects on energy consumption patterns

- Atmospheric pressure: Can influence weather-sensitive industrial processes and correlates with other meteorological variables

- Weather forecast horizon: Accuracy of weather predictions decreases with time, directly affecting forecast uncertainty in OpenSTEF's probabilistic outputs


OpenSTEF models exhibit distinct seasonal and temporal patterns in feature importance that reflect the underlying dynamics of energy consumption. During winter months, heating-related features such as temperature and wind chill typically show increased importance, while summer periods see greater emphasis on cooling degree days and solar radiation features. The library's feature engineering modules automatically capture these seasonal variations through cyclic features that encode time-of-year information, allowing models to adapt their reliance on different predictors throughout the annual cycle. Temporal patterns also emerge at shorter time scales, with lag features showing varying importance depending on the forecast horizon - recent historical load values are typically most important for near-term predictions, while weather features gain prominence for longer forecast horizons. Weekend and holiday features demonstrate strong temporal patterns, with their importance fluctuating based on the day of the week and proximity to special events. The rolling features module captures these temporal dependencies by creating moving averages and statistical measures over different time windows, enabling the model to recognize recurring patterns in feature importance that align with human activity cycles and seasonal energy demand variations.


.. note::

   Feature importance varies significantly across different locations, grid types, and use cases. What drives predictions for industrial areas may differ greatly from residential neighborhoods or renewable energy installations. The OpenSTEF library's feature engineering modules automatically adapt to your specific context, but understanding your local patterns - such as weather sensitivity, load profiles, and seasonal variations - will help you interpret model outputs and validate forecast quality for your particular application.


Fallback Strategies and Model Reliability
-----------------------------------------


In production energy forecasting systems, forecast availability is absolutely critical - system operators and energy traders cannot afford gaps in their forecasting capabilities. OpenSTEF addresses this challenge by implementing multiple fallback strategies that ensure a forecast is always available, even when primary models fail or encounter unexpected conditions. These fallback mechanisms are essential because energy systems operate continuously, and decision-makers need reliable predictions to maintain grid stability, optimize trading positions, and ensure supply-demand balance. When OpenSTEF deploys a fallback forecast, it clearly labels it as such, providing full transparency about which forecasts were used as the basis for operational decisions. This robust approach to handling model failures makes OpenSTEF particularly well-suited for mission-critical applications where forecast reliability can have significant economic and operational consequences.


- Missing or incomplete input data (weather forecasts, historical measurements, or external features)

- Model training failures due to insufficient historical data or data quality issues

- Poor model performance metrics falling below acceptable thresholds during validation

- Infrastructure failures preventing model execution or prediction generation

- Data pipeline interruptions causing gaps in feature preparation

- Model convergence issues during hyperparameter optimization

- Corrupted or invalid model artifacts that cannot be loaded for prediction

- External data source outages affecting critical input features

- Memory or computational resource constraints preventing model execution

- Unexpected data format changes breaking the prediction pipeline


.. code-block:: python

   ```python
   from openstef.model.fallback import create_fallback_forecast
   from openstef.model.regressors.flatliner import FlatlinerRegressor
   from openstef.model.regressors.median import MedianRegressor
   import pandas as pd
   import numpy as np

   # Define prediction data with datetime index
   prediction_data = pd.DataFrame({
       'datetime': pd.date_range('2024-01-01', periods=48, freq='15T'),
       'load_forecast': np.nan,  # Primary forecast failed
       'temperature': [5.2, 5.1, 4.9, 4.8] * 12,
       'wind_speed': [3.1, 3.3, 3.2, 3.0] * 12
   }).set_index('datetime')

   # Historical data for fallback models
   historical_data = pd.DataFrame({
       'datetime': pd.date_range('2023-12-01', '2023-12-31', freq='15T'),
       'load': np.random.normal(100, 20, size=2976),
       'temperature': np.random.normal(5, 2, size=2976)
   }).set_index('datetime')

   # Strategy 1: Use median of recent historical values
   median_fallback = MedianRegressor()
   median_fallback.fit(historical_data[['load']])
   median_forecast = median_fallback.predict(prediction_data)

   # Strategy 2: Use flatliner (last known value)
   flatliner_fallback = FlatlinerRegressor()
   flatliner_fallback.fit(historical_data[['load']])
   flatliner_forecast = flatliner_fallback.predict(prediction_data)

   # Combine fallback strategies with priority
   def apply_fallback_strategy(primary_forecast, fallback_forecasts):
       """Apply fallback forecasts when primary forecast fails"""
       result = primary_forecast.copy()

       # Use median fallback for missing values
       mask_missing = pd.isna(result)
       if mask_missing.any():
           result[mask_missing] = fallback_forecasts['median'][mask_missing]

       # Still missing? Use flatliner as last resort
       mask_still_missing = pd.isna(result)
       if mask_still_missing.any():
           result[mask_still_missing] = fallback_forecasts['flatliner'][mask_still_missing]

       return result

   # Apply fallback strategy
   fallback_forecasts = {
       'median': median_forecast,
       'flatliner': flatliner_forecast
   }

   final_forecast = apply_fallback_strategy(
       prediction_data['load_forecast'],
       fallback_forecasts
   )

   # Label forecast source for transparency
   forecast_source = pd.Series('fallback_median', index=prediction_data.index)
   forecast_source[pd.isna(median_forecast)] = 'fallback_flatliner'

   print(f"Fallback forecast generated for {len(final_forecast)} time periods")
   print(f"Sources used: {forecast_source.value_counts().to_dict()}")
   ```


OpenSTEF implements multiple fallback strategies to ensure forecast availability is never compromised, which is critical in energy sector applications. The library provides several types of fallback models that activate when primary models fail or produce unreliable results. Persistence models serve as the simplest fallback, using the most recent observed values to generate forecasts by assuming current conditions will continue. Simple averaging models calculate forecasts based on historical averages, such as using the same hour from previous days or weeks to handle seasonal patterns. The library also supports more sophisticated backup models that can include secondary machine learning models with different architectures or feature sets, providing a more robust alternative when the primary model encounters issues. When any fallback forecast is issued, OpenSTEF explicitly labels it as such, enabling full traceability of which forecasts were used for decision-making and maintaining transparency in the forecasting process.

Forecast Horizons and Temporal Patterns
---------------------------------------


Forecast horizons define how far into the future OpenSTEF can make predictions, typically measured in hours or days ahead. The accuracy of forecasts generally decreases as the prediction horizon extends further into the future, with short-term forecasts (minutes to hours) being more reliable than long-term predictions (days to weeks). OpenSTEF enforces minimum horizon requirements - for example, component forecasts must be at least 30 minutes in advance to ensure meaningful predictions. The library's forecasting models are designed to handle multiple horizons simultaneously, allowing users to configure maximum lead times and create predictions for different time ranges. Understanding these temporal limitations is crucial for setting realistic expectations and choosing appropriate forecast horizons for your specific use case.


.. image:: _static/images/placeholder_graph_showing_forecast_accuracy_degradation_over_increasing_time_horizons.png
   :alt: Graph showing forecast accuracy degradation over increasing time horizons
   :align: center


Energy forecasting accuracy typically follows predictable temporal patterns, with performance degrading as the forecast horizon extends further into the future. Short-term forecasts (15 minutes to 1 hour ahead) generally achieve the highest accuracy due to the strong autocorrelation in energy consumption patterns and the limited time for external factors to introduce uncertainty. As the horizon extends to several hours ahead, accuracy gradually decreases as weather uncertainties, demand variations, and other external factors compound. The OpenSTEF library enforces a minimum forecast horizon of 30 minutes to ensure meaningful predictions, as forecasts with shorter horizons may not provide sufficient lead time for operational decision-making. Beyond 24-48 hours, forecast accuracy can decline significantly, particularly during periods of high volatility or extreme weather events, making it essential to understand these temporal accuracy patterns when designing forecasting workflows and setting appropriate expectations for different prediction horizons.


.. code-block:: python

   ```python
   from openstef.model.regressors import ARimaRegressor
   from openstef.data_classes.prediction_job import PredictionJobDataClass
   import pandas as pd

   # Create a prediction job with multiple horizons
   pj = PredictionJobDataClass(
       id=123,
       name="wind_farm_forecast",
       model="arima",
       horizons=[0.25, 1.0, 6.0, 24.0, 47.0]  # 15 min, 1h, 6h, 24h, 47h
   )

   # Initialize the forecaster
   forecaster = ARimaRegressor()

   # Generate forecasts for different horizons
   results = {}

   for horizon in pj.horizons:
       # Create forecaster configuration for specific horizon
       horizon_config = forecaster.with_horizon(horizon)

       # Generate forecast for this horizon
       forecast = horizon_config.predict(
           data=input_data,
           prediction_job=pj
       )

       results[f"horizon_{horizon}h"] = forecast
       print(f"Forecast for {horizon}h horizon: {len(forecast)} predictions")

   # Access maximum supported horizon
   max_horizon = forecaster.max_horizon()
   print(f"Maximum forecast horizon: {max_horizon} hours")

   # Generate forecasts for short-term (0.25h) vs long-term (47h)
   short_term = forecaster.with_horizon(0.25).predict(input_data, pj)
   long_term = forecaster.with_horizon(47.0).predict(input_data, pj)

   print(f"Short-term forecast accuracy typically higher")
   print(f"Long-term forecast shows broader trends but higher uncertainty")
   ```


- For 15-minute horizons: Use high-frequency features and recent data patterns, as short-term forecasts rely heavily on immediate trends and weather conditions

Forecast quality in OpenSTEF varies significantly based on temporal patterns inherent in energy systems. Daily patterns, such as morning and evening demand peaks, are generally well-captured by the library's models, resulting in higher accuracy for short-term horizons within familiar daily cycles. Weekly patterns introduce additional complexity, as weekday versus weekend consumption behaviors differ substantially, requiring the forecasting models to distinguish between these recurring patterns. Seasonal variations present the greatest challenge to forecast accuracy, as longer-term weather dependencies, heating and cooling demands, and daylight variations create complex interactions that become increasingly difficult to predict accurately over extended horizons. The library's feature engineering capabilities help capture these temporal patterns through holiday features, time-based features, and weather correlations, but forecast uncertainty naturally increases as predictions extend further into periods where seasonal transitions or unusual weather patterns may disrupt established temporal relationships.
